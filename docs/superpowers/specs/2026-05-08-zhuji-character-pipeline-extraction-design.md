## 第一部分设计：char0~7 角色创建管线

### 通用格式

每个 char_step 章节包含：
1. **目标** — 本步骤产出的角色维度
2. **操作流程** — agent 执行步骤（提问/生成/确认）
3. **输出格式** — 产出写入角色卡的具体 Markdown 结构
4. **衔接说明** — 进入下一步骤的前置检查

### char0 — 概念设计

**目标：** 建立角色核心概念框架，为后续外显/内质/外延三轴解构奠基。

**操作流程：**
1. agent 根据用户对角色初步描述，判断使用哪个模板：
   - **大丨标准化模板**（通用，所有角色类型）
   - **风空精神分析模板**（心理复杂度高的角色）
   - **心理动力学网络构架模板**（需避免 OOC 的角色）
2. 按选定模板向用户提问，覆盖：角色在故事中的功能、核心矛盾、关键关系、变化弧光
3. 产出 200–400 字角色概念摘要，用户确认

**输出：** 角色卡「身份定位」字段（身份/目标/动机/核心冲突/弧光笔记）。

### char1 — 外显模块

**目标：** 角色外貌/身体/声音/气味/服装。

**操作流程：**
1. 依次提问 5 个外显维度
2. 每个维度追问行为具体性
3. 注意外显与内质的反差关系（如幼小身躯+成熟气质）
4. 生成外显描述摘要，用户确认

**输出：** 角色卡「简介」字段的外貌部分。

**提示：** 如用户启用官能内容，可激活色情化外显维度（prompt 117）。

### char2 — 内质模块

**目标：** 人格/驱动力/动机/世界观体系。

**操作流程：**
1. 人格类型（可选 MBTI/Enneagram 框架）
2. 核心驱动力（什么让他早上起床？）
3. 压力下与放松时的行为差异
4. 不自知的盲点
5. 自我认知 vs 他人评价的差距

**输出：** 角色卡「性格」「简介」字段的内在部分。

### char3 — 外延模块

**目标：** 社会属性/人际关系/成长经历/关键事件。

**操作流程：**
1. 社会阶层与身份
2. 关键人际关系（与后续 char6 互补——char3 聚焦角色自身视角，char6 聚焦关系网络分析）
3. 成长经历时间线
4. 塑造角色的关键事件
5. 可选补充拓展（恋爱史、教育背景等）

**输出：** 角色卡「情景设定」「深层设定」字段的社会属性部分。

### char4 — 特质细化

**目标：** 5–8 个核心特质，每个含具体行为示例和语言示例。

**操作流程：**
1. 从 char0~3 产出中提取 5–8 个关键特质
2. 对每个特质，追问：行为示例（他在什么情境下如何表现？）、语言示例（他为此说什么话？）
3. 呈两组特质化方案供用户选择：
   - **桐谷申元化（诗意版）** — 文学性表达
   - **心理动力学网络构架版** — OOC 避免强化
4. 整合特质列表，用户确认

**输出：** 角色卡「性格」字段的细化版。

### char5 — 语料生成

**目标：** 角色自我介绍、场景对话示例、特质化语料。

**操作流程：**
1. 生成「角色自述」（第一人称自我介绍，200–300 字）
2. 生成 3 个场景对话：
   - 说服别人时（对话作为行动/操控）
   - 表达脆弱时（对话作为暴露/求助）
   - 日常寒暄时（对话作为面具/维护）
3. 生成特质化语料（将 char4 特质转化为对话片段）

**输出：** 角色卡「对话风格」字段（含场景对话），「开场呈现」字段（基于语料提炼）。

### char6 — 关系网络

**目标：** 本角色与其他角色的关系网络。

**操作流程：**
1. 一对一关系（与每个已知角色的关系描述）
2. 小团体分析（本角色属于哪些群体/阵营）
3. 关系稳定性/冲突分析
4. 将产物写入 `20-story/character-relationships.md`（非仅角色卡内部）

**输出：** 更新 `character-relationships.md` 中涉及本角色的所有条目。

### char7 — 概念设计（视觉）

**目标：** 角色视觉概念 AI 生图提示。

**操作流程：** 可选。如用户需要角色插图，根据 char1 外显信息生成生图提示。

**输出：** 角色卡「创作者备注」字段或独立视觉文档。

**标记：不可阻塞。** 标注「低优先级，可跳过」。

## 第二部分设计：角色审查

**位置：** char0~7 流程完成后执行。

**流程：**

1. **一致性诊断** — 检查角色各维度间是否存在矛盾（如 char2 描绘的懦弱人格 vs char1 描绘的挑衅性穿着）
2. **深度与维度诊断** — 角色是否有足够层次（扁平角色 vs 圆形角色），是否需要补充 char3/char4
3. **漏洞优化** — 空白的必要维度补全、模糊定义的具体化

**前置条件：** 需要知识库《人物》（麦基）的支持（对应子项目四的 `references/theory/mckee-character.md`）。

**输出：** 审查结论 + 修改建议，返回对应 char_step 修订。
